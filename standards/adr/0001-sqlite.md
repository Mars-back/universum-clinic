# SQLite для обліку пацієнтів

## Контекст і проблема

Застосунок створює та повертає списки пацієнтів, лікарів і прийомів.
Дані мають зберігатися після зупинки сервера. Для поточного обсягу потрібен
простий локальний запуск без окремого сервера бази даних і пароля.

## Критерії рішення

- Збереження даних після перезапуску.
- Підтримка зв'язків між трьома таблицями.
- Створення початкової схеми через JavaScript.
- Невелика кількість налаштувань і зрозумілі SQL-запити.

## Розглянуті варіанти

| Варіант                     | Переваги                                                       | Обмеження                                                                     |
| --------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Масив у пам'яті JavaScript  | Просте додавання та читання об'єктів                           | Дані втрачаються після зупинки процесу; немає SQL і зовнішніх ключів          |
| SQLite через better-sqlite3 | Дані у файлі, SQL і зовнішні ключі; не потрібен окремий сервер | Потрібна сумісна версія пакета для встановленої Node.js                       |
| PostgreSQL                  | Окремий сервер БД, SQL і зовнішні ключі                        | Для цього локального API додає налаштування сервера, користувача та з'єднання |

## Рішення

Використовувати SQLite через better-sqlite3. Вона виконує вимоги збереження
та зв'язків без окремого сервера. Масив у пам'яті не виконує вимогу
збереження; налаштування PostgreSQL не потрібне поточному обсягу.

src/config/database.js відкриває data/clinic.db, вмикає foreign_keys
і створює таблиці patients, doctors та appointments через CREATE TABLE IF NOT EXISTS.
appointments.patient_id посилається на patients.id,
appointments.doctor_id — на doctors.id. Обидва зв'язки обов'язкові.

## Наслідки

База створюється при першому звичайному запуску та зберігається у локальному файлі.
У тестах використовується окрема БД :memory:, тому робочі дані не змінюються.
Значення передаються в SQL через параметри ?, а не склеюються з текстом запиту.

Версія better-sqlite3 зафіксована у package.json і package-lock.json для
відтворюваного встановлення. CREATE TABLE IF NOT EXISTS створює відсутні таблиці,
але не змінює структуру вже наявних: майбутня зміна схеми потребуватиме окремого рішення.

## Підтвердження

npm run check перевіряє API, дані та помилки зовнішніх ключів у тестовій БД.
Окремо збереження у файлі перевіряється створенням запису, перезапуском сервера
та повторним GET-запитом. Файл data/clinic.db і node_modules не додаються в Git.
